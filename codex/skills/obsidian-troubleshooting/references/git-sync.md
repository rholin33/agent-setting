# Git 私有知识库同步

目标和接入状态见 `local-vault.md`。所有 Git 命令显式指定 `-C <vault>`；不得对当前业务仓库执行知识库操作。使用现有 GitHub CLI 凭据助手，不读取令牌、复制其他凭据或将秘密存入库。

## 记录和检索

1. 核对真实目录、`remote get-url origin`、分支和 `status --porcelain`。发现 merge/rebase 未完成或冲突时先报告，不能丢弃内容继续。
2. `fetch origin` 取得最新远端。工作区干净时 `pull --ff-only`；工作区已有改动时，不自动 stash、reset 或覆盖，应先比较本地和远端涉及的路径。取回失败可以处理本地笔记，但要明确未确认云端最新状态。
3. 查重、读写和验证遵循主技能。保存后仅 `git add -- <本次笔记路径>`，检查暂存内容无秘密、无无关文件；已有他人暂存变更时不要一并提交。`.obsidian/`、`.trash/` 不进入提交。
4. 提交本次记录后普通 `push origin main`。若被拒绝，重新 fetch 并分析；不得强推。与后台插件并发时先核对是否已提交／上传，不重复创建相同提交，也不删除活动中的 Git 锁文件。
5. `fetch origin` 后确认本次提交是 `origin/main` 的祖先，并检查目标笔记在远端分支中的内容。最终区分“本地已保存／已提交”和“已同步 GitHub”。鉴权或网络失败保留本地记录并报告待同步。

## Obsidian Git

本机计划每 5 分钟自动提交并同步、每 5 分钟拉取、启动拉取。插件只有应用打开且库已加载时才运行；agent 可在应用关闭时独立同步。应用使用中更新笔记后尽快提交，避免插件与 agent 同时操作索引。

不同设备独立安装插件及配置凭据，不能把 `.obsidian/plugins/.../data.json` 当作跨设备凭据通道。移动端为实验性支持，不承诺与桌面端同等可靠性。

## 故障处理

- 本机系统代理为 `127.0.0.1:10808`；仅此库配置 `http.proxy`，依赖代理程序运行。不要修改全局代理。代理改变时先核实再更新本库。
- 仓库使用 `http.sslVerify=true`；不能通过关闭证书验证解决连接失败。
- GitHub CLI 未登录时，在可见终端走浏览器授权；用户自行完成账号和验证码步骤。浏览器登录不等于 CLI 已授权。
- 自动同步冲突：保留双方内容，给出具体冲突文件并请求必要的语义决策。不做自动 ours/theirs 整体覆盖。
