# 官方 Sync

用户选择 Obsidian 官方 Sync。使用本机偏好中的客户端和绑定目录；Headless 可独立工作，不要求 Obsidian 桌面应用运行。本地 Markdown 是云端库的同步副本。

## 绑定与身份

`node <client> sync-list-remote --json` 列出可用云端库，`sync-list-local --json` 核对本地绑定。只连接用户选定的库；列表为空不等于登录失败，也不能推断订阅状态。首次新建库和同步目录先落实用户选择，不能把当前业务仓库当成知识库。

登录使用本机可见交互终端运行 `node <client> login`。账号密码、MFA 和端到端加密密码由用户在终端输入，不在聊天索取、不作为命令行参数、不读取凭据存储。

绑定命令为 `node <client> sync-setup --vault <id-or-name> --path <absolute-path>`。端到端加密时保留交互密码提示，不能用禁用提示的 `--json` 或把密码写入脚本。完成后把真实库名、远端 ID、绝对本地目录写入本机偏好，不保存秘密。

## 每次记录／检索

1. 核对绑定路径，运行 `node <client> sync --path <absolute-path>`，等待一次同步结束，再搜索和读取。同步失败时说明云端新鲜度未确认，不把旧副本检索视为全库最新结果。
2. 依照主技能查重并写入；重新读取验证 Markdown 和属性。
3. 写入后再次执行一次同步，检查退出码、上传记录及 `node <client> sync-status --path <absolute-path> --json`。只有得到实际同步成功证据才能报告云端已同步；单有绑定信息或文件存在不够。
4. 同步失败保留本地记录，明确标注“本地已保存，云端待同步”，修正原因后再重试。不要启动无限重试或为绕过故障改为其他云服务。

日常操作不创建远端库、不切换绑定、不修改同步方向、不启用系统启动项。此流程按任务执行一次同步，不承诺任务外持续后台同步。不要调用 `publish`：官方 Sync 私有同步与 Publish 公开发布是不同服务。
