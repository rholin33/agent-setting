# 本机 Pi 配置同步到 OMP

## 方向和范围

固定方向：**本机 Pi → 本机 OMP**。Pi 是配置来源，OMP 是写入目标。
“同步 OMP 配置”表示把 OMP 配置成与本机 Pi 相同，不能反过来修改 Pi，
也不能按模型数量、修改时间或当前运行的客户端选择来源。
若用户明确要求反方向或双向同步，说明本技能的方向，按新的明确要求另行处理。

这是本机配置对齐，不运行 agent-setting-sync，不要求 ccb/orca 目标，
不拉取、提交或推送仓库，不修改 Orca 团队配置，不重启任何现有会话。
用户要求同步即授权本次兼容配置写入，无须重复确认同一范围。

## 定位及预览

默认来源 `~/.pi/agent`，默认目标 `~/.omp/agent`；`~` 必须按当前操作系统解析。
有显式配置目录、OMP profile 或环境变量覆盖时，先核实实际目录。
`PI_CODING_AGENT_DIR` 在两个客户端中都有含义，不能将它同时作为两边目录。
禁止来源与目标解析为同一路径，遇到链接时核实实际指向。

先查看两边适用的 AGENTS.md，读取 Pi 的 `settings.json`、`models.json`，
及 OMP 当前生效的配置。OMP 优先使用 `config.yml` / `config.yaml`、
`models.yml` / `models.yaml`；旧 `settings.json` 或 `models.json` 不能覆盖原生 YAML 的优先级。
结合本机已安装版本的帮助、文档或解析器确认兼容格式。

记录 Pi 来源文件的哈希，比较目标后用简短说明列出将修改的路径和字段。
预览只展示模型名、设置项和差异统计，屏蔽 API key、Token、请求头等秘密。
若 Pi 的默认模型未在其模型列表中，明确报告这一来源问题，保留用户原选择；
不能静默换成其他模型、凭空添加模型定义，或把目录校验成功说成默认模型可用。

## 配置映射

| Pi 来源 | OMP 目标与处理 |
| --- | --- |
| `models.json.providers` | 转换为 OMP 原生模型 YAML。以 Pi 列表及模型参数为准，备份后替换该映射，不合并保留 OMP 独有提供商或模型。其他 OMP 顶层字段保留。 |
| `defaultProvider`、`defaultModel` | 转为 `modelRoles.default` 的 `provider/model`。按当前 OMP 版本支持的语法附带思考等级；模型 ID 可含 `/`，不可错误拆分。 |
| `defaultThinkingLevel` | 同步到 OMP 对应字段，并使默认角色中的等级一致。 |
| `hideThinkingBlock`、`modelThinkingLevels` | 同步同义设置，保留模型 ID 原文。 |
| 内置 `theme` 为 `dark` 或 `light` | 映射到 OMP 对应主题设置；若使用 light/dark 映射，仅更新对应项。自定义主题先确认可用，不能直接假定跨客户端兼容。 |
| `compaction.enabled` | 同步对应开关。来源未设置时查明 Pi 当前版本的实际默认值；来源缺省不等于 false。OMP 专用的异步、轮中压缩设置保留。 |
| `AGENTS.md` | 文件存在且用户请求通用配置对齐时同步，内容一致则跳过。 |
| `skills/` | 按相对路径同步 Pi 的技能及所需资源；备份同名差异，保留 OMP 独有技能，不做删除镜像。核实链接指向，跳过缓存及运行产物。 |

OMP 中存在旧 `models.json` 时，检查它是否仍被辅助工具使用。需要保持兼容时，
一并对齐为相同的 Pi 模型内容；不存在时不为兼容而新建旧格式文件。
模型提供商中的本机凭据可随这次明确授权的本机配置对齐写入 OMP，
仅保存在本机及受保护备份中，不能输出或上传。不要复制 `auth.json`、OAuth 登录状态或账户数据库。

保留各客户端专用扩展、插件和依赖。尤其不能把 Pi 的 `packages`、
`-builtin:mcp`、Orca `/hook/pi`、`ORCA_PI_PREFILL` 等原样覆盖到 OMP；
OMP 的 `/hook/omp`、`ORCA_OMP_PREFILL` 及专用生命周期逻辑必须保留。
Pi 相对路径如 `skills` 应按来源目录解释，再映射到目标目录，不能照抄错误路径。

MCP 先比较有效配置及共享来源，如 `~/.config/mcp/mcp.json`。
共享配置已一致则跳过；有实际差异时核对两种客户端的字段语义再转换，
例如 `requestTimeoutMs` 与 `timeout` 的单位需查明。不要复制 `mcp-cache.json`。
未确认兼容的设置保留目标值，报告具体未同步项。

## 写入、验证和交付

1. 在 OMP 的 `~/.omp/backups/pi-config-sync-<唯一时间标识>/` 或对应覆盖目录下，
   保存将被改动文件的原始字节及清单；清单记录方向、绝对路径和哈希，不记录秘密值。
   这是恢复备份，应保留并报告路径，不能作为临时文件自动清理。
2. 先在操作系统临时目录 API 创建的任务独立目录内生成候选文件并校验格式。
   检查来源和目标未在准备期间变化，再写入；发现并发修改则停止覆盖并重新比较。
   多文件应用失败时从备份恢复本轮已经修改的目标文件，不碰 Pi。
3. 重新读取磁盘，核对模型映射和设置语义；验证 Pi 所有来源文件哈希未变，
   专用扩展及排除项未变。优先使用已安装 OMP 的原生模型解析/列举功能，
   在隔离临时配置目录中验证，避免创建真实会话、更新运行数据库或发起模型推理。
   不能将 `models refresh` 当作只读验证。
4. 对可用模型、默认模型及仅完成语法校验的情况分别如实报告。
   报告修改文件、备份位置、保留差异和生效方式；现有会话需要重新加载时告知用户，
   不擅自重启。关闭本轮句柄和进程后在 finally 中清理本轮临时目录。

不要删除文件、会话、数据库、日志、缓存、历史备份或其他客户端配置来实现同步。
本次请求只创建/更新本技能时，不顺带执行一次配置同步。
