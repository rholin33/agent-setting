# 轻量任务执行规则

当任务属于明确 bug、小功能、配置、样式、文案或少量测试修改，且预计只涉及 1～3 个文件时，按轻量流程处理。

1. 直接定位相关代码，完成最小必要修改，并运行一个最相关的验证。
2. 不默认创建计划、文档、ADR、worktree、分支、提交或子代理任务。
3. 不进行无关重构、依赖升级、目录整理、格式化或“顺手修复”。
4. 不为假设风险增加兼容层、重试、回退、日志、过量校验或其他防御性代码。
5. 能从项目和现有代码确定的内容不要询问；只有关键行为无法判断时才提一个问题。
6. 默认只运行单个相关测试、局部类型检查、lint 或构建。不得默认执行全量测试、多平台验证、性能测试或安全扫描。
7. 仅在用户要求、逻辑容易回归或现有测试结构适合时新增测试。
8. 涉及公共 API、数据库、认证、权限、支付、数据删除或跨模块契约时，才扩大分析与验证范围。
9. 需求实现且相关验证通过后立即停止，不为追求“完全稳妥”继续扩展工作。
10. 最终只需说明修改内容、关键文件及验证结果。
